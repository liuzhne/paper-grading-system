# 评分标准：评分项与评分规则

参考设计：<https://claude.ai/design/p/f235ec89-9ec1-4825-853b-5e62f5f8e7f0?file=评分标准-评分项与规则.dc.html&via=share>。

2026-09-29 按新设计组织：第 1 步核对文件、评分项与分值；第 2 步组织待归类原文、逐评分项规则来源、AI 起草与最终细则确认；第 3 步校验与发布。标题下保留三步导航，右上角保留新建评分标准与模板库。评分项、分值、数量、文件名、章节与模型连接全部来自当前草稿；不使用设计中的示例 T01–T06、448 段或固定的 100 分。

## 前端与接口

所有路径前缀为 `/api`，沿用现有登录、组织可见性和教师/管理员写权限。

| 页面操作 | 前端模块 | 接口与数据 | 行为 |
|---|---|---|---|
| 导入及确认 | RubricImportWorkspace | POST `/rubrics/import-sessions`，PATCH 会话，POST `/rubrics/import-sessions/{id}/confirm` | 继续使用带状态版本的临时导入会话 |
| 文件名、来源、原文上下文 | RubricsView / SourceReviewPanel | GET `/rubrics/{id}/source-workspace` | `files`、`file_metadata`、`criteria.source_refs`、`previews`；现有 `locator` 字典附带台账 `review` 投影 |
| 分步计数、门禁 | RubricImportWorkspace | GET `/rubrics/{id}/parse-coverage` | `coverage`、`conflicts`；来源冲突阻止进入第 2 步；疑似规则在第 2 步处理，后端发布校验继续兜底 |
| 列用途、表头、评分行、合计行 | TableRecognitionPanel | 同上 `extraction` | 列号转 A/B/C；不推测空白单元格是满分列 |
| 原表对照 | TableRecognitionPanel | `source-workspace.previews.excel` | 按原单元 ID 的行列展示原文；不修改文件 |
| 原表「识别为」列 | TableRecognitionPanel | `parse-coverage.extraction` 的 `header_row/records/total_row/dropped_rows`，以及单元格 `locator.review.claimed_by` | 标出表头、评分项 → 编号、合计 · 不计入、未计入原因、其他工作表；不按显示次序猜测对应关系 |
| 分值核对 | RubricImportWorkspace | 当前编辑表单 + POST `/rubrics/{id}/recompile` | 无独立满分列时先逐项/全部核对；本次页面核对提示不冒充服务端审批记录，刷新重新核对 |
| 保存草稿、下一步 | RubricsView | 有修改才 POST `/rubrics/{id}/recompile`，随后重新读取草稿 | 校验成功后进入第二步；不自动发布 |
| AI 结构识别估算 | TableRecognitionPanel | POST `/rubrics/{id}/structure-suggestions`，`dry_run:true` | 不调用模型，显示字符量与调用次数 |
| 确认 AI 识别 | 同上 | 同一路径，`ai_connection_id` | 采用当前启用的个人连接；无启用连接时按钮禁用 |
| 按行核对字段差异 | StructureSuggestionPanel | `structure_suggestions.items` | 唯一来源行优先匹配，保留编号；名称、满分、说明等修改逐项确认 |
| 合入 / 撤销 | StructureSuggestionPanel | POST `/rubrics/{id}/suggestions/merge` / `undo` | 指纹校验；未确认字段保留当前值；真正移除仍阻断；生成新草稿 |
| AI 归类建议 | SourceReviewPanel | POST `/rubrics/{id}/unit-classifications`，`unit_ids`、`ai_connection_id` | 优先提交选中单元，否则提交当前筛选的待处理单元；8192 默认预算尊重连接显式上限；结果显示成功/失败/未返回与安全错误原因，支持失败重试，保留其它有效建议 |
| 单条 / 批量归入或不是规则 | SourceReviewPanel | POST `/rubrics/{id}/units/resolve-batch`，`unit_ids`、`action`、`criterion_code`、`reason` | 原文不变，服务端记录人工台账和审计；失败保留当前选择 |
| 采纳高置信建议 | SourceReviewPanel | 复用 `resolve-batch`，按动作/评分项分组 | 仅非过期、高置信且目标评分项仍存在的建议；失败停止，刷新已完成结果；不声称跨请求原子性 |
| 单条采纳 AI 建议 | SourceReviewPanel（列表行内与右侧建议卡） | 复用 `resolve-batch`，`assign` 或 `not_rule`，理由「用户采纳 AI 归类建议」 | 仅待处理单元、建议未过期、建议的评分项仍存在时可采纳；只读与请求中禁用 |
| 第 2 步阻断项 | RubricsView 底栏 | `parse-coverage`、`rule-coverage`、`review-workspace`、编译 blockers、未应用 AI 草稿 | 与「保存规则，下一步」的禁用条件逐项对应，按类别汇总；点击打开疑似规则筛选或该类第一个评分项 |
| 移出/恢复原文 | SourceReviewPanel / RubricsView | 既有 `resolve-batch` 的 `action:restore` | 撤销人工 `.manual` 归属，恢复待归类；自动抽取的归属保留；追加审计 |
| 当前评分项规则来源 | RubricsView | `source-workspace.previews.*.locator.review.claimed_by` + 评分项 `description/deduction_rules` | 不复制原文、不新增评分项；来源变化清除页面未应用的 AI 建议 |
| AI 根据规则来源起草 | RubricsView | POST `/rubrics/{id}/draft-deduction-rules` | 后端读取真实台账中 `<code>.manual` 内容，携带原始 unit_id 进入 `input_analysis.unresolved_segments/source_refs`，输出仍是待人工核对建议 |
| 应用/确认细则 | AiRuleDraftPanel / RuleReviewPanel | 既有 recompile / rules/{code}/confirm | 应用生成新执行草稿，正式确认记录版本、内容指纹及操作者；不自动发布 |
| 来源冲突 | ParseCoveragePanel（conflictsOnly） | 同一 `resolve-batch` | 以 Excel 为准或指派既有评分项，不新增 Word 评分项 |
| 重传文件 | RubricImportWorkspace | POST `/rubrics/{id}/reupload-preview` / `reupload-confirm` | 对比后确认替换；分值/评分项修改沿用现有审核失效规则 |

快捷键仅在原文工作区获得焦点且焦点不在输入框、下拉框或按钮中有效：1–9 归入前九个评分项，X 不是规则，J/K 切换。全部评分项均提供按钮；没有写死六项。处理成功后定位下一条；只读和请求中不允许修改。

## 门禁与持久化

新增的是既有 action 枚举值和既有 JSON 内的审计内容；没有新增数据库列、表或端点，复用 `raw_parse_output/raw_model_output/human_changes`，Alembic head 保持 `0032_single_active_ai_connection`，无数据迁移。前端类型由 OpenAPI 重新生成。全局 prompt version 为 `2026-09-30-1`，分类器 `rubric-unit-classify@3`，规则起草 `rubric-rule-draft@8`（2026-09-30 起在输入中列出可用来源，并把批内位置指针改写为原文编号）。

第 1 步只校验分值/必填字段/来源冲突。第 2 步底部“保存规则，下一步”要求阻断原文、缺失细则、待确认规则及未应用 AI 建议处理完成。顶部仍可进入校验页查看既有诊断；后端发布 gate 不放宽。分值核对仍属于当前页面会话，刷新重新核对。

## 与原型的明确差异

- 原型推测的 `validation.blockers`、统一 `source{type,ref}` 不新造同义 API；读取现有 coverage、compilation blockers、source_refs 和台账引用。
- 规则“排除”沿用现有暂不纳入本次批量确认语义，可撤销，仍需处理后才能发布；不是永久删除已授权规则。移出来源也不会撤销已生成细则，需要另行核对。
- 不把分档制或人工复核条款强行显示成扣分制；保留现有编辑器及发布完整度检查。
- 后端台账包含段落、批注、表格单元格，统一标为“单元”，不把单元格数冒充段落数；上下文包含原文相邻单元，章节优先采用来源记录，缺失时显示“未标注章节”。
- “已排除或作为上下文”同时涵盖结构/上下文/忽略状态，不能全部称为“自动排除”；已处理页读取真实人工标记。
- 不提供没有后端契约的“手动调整列与行”空按钮。人工直接修改评分项字段或重传评分表走现有校验链；结构差异可逐字段保留/采用。
- 真正缺行、重复或歧义来源仍不能强行合入。行号只有在当前工作表内一对一对应时才建立身份，不能拿显示次序猜测对应关系。
- 仍支持仅 Word 导入，与双文件场景的“Excel 决定评分项”文案区分。
