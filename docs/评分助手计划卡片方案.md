# 评分助手计划卡片：先列出步骤，再按步骤走

状态：已实施（2026-10-28，与“开始评分先查前提”同日；维护者要求写方案并实施）
关联：`docs/对话评分助手改造方案.md` §4、§7.3–§7.4；`docs/评分助手Agent化方案.md`；DECISIONS 2026-10-28 两条

## 1. 背景

2026-10-28 生产上，老师说“开始评分”，助手直接弹选文件；问“现在有评分标准吗？”才知道没有。维护者提出两点：

1. 开始评分前应该先检查有没有评分标准；
2. 老师和 Agent 交互评分时，是否应该用 Plan–Execute：先规划有几步，再按步骤做。

第 1 点已在同日改掉（DECISIONS“开始评分先查评分标准与模型”）：缺评分标准或评分模型时不弹选文件，说明怎么补。本方案回答第 2 点。

## 2. 结论：计划由代码列出，执行仍是流程图

评分的步骤是固定的，事先知道：

> 评分标准 → 评分模型 → 选文件 → 确认 → 上传与预检 → 评分 → 汇报

Plan–Execute（模型先列步骤、逐步执行、必要时重新规划）适合事先不知道要走哪几步的任务。用在这里，模型可能漏掉确认、排错顺序，而建任务、开评都是写操作，必须每次一样、可审计；改提示词还要重跑真实模型评测。

Plan–Execute 真正有用的是“开工前让老师看到要走几步、现在在哪一步”。这一点由代码做：流程开始时按前提检查的结果列出步骤，做成一张**计划卡片**，流程每走一步就在原卡片上更新。模型不决定有哪几步，也不碰分数（Agent 化方案的红线不变）。

## 3. 计划卡片

### 3.1 什么时候出现

| 流程 | 出不出计划卡片 |
|---|---|
| 开始评分，前提都满足 | 出，7 步 |
| 开始评分，缺评分标准或评分模型 | 不出：只说明缺什么、给入口（前提检查那条决定），流程结束 |
| 导入评分标准（说“上传我的评分规则和模板”、点按钮，或缺标准时点“用我的评分规则和模板”） | 出，8 步：导入流程发布后本来就接着评分 |
| 重试失败项后的观察（watch） | 不出：只有“等评分结束”一步，进度卡片已经够了 |

计划卡片是流程的第一条消息：“这次评分的步骤如下，每走完一步我会在这里更新。”

### 3.2 步骤

开始评分（7 步）：

| 键 | 名称 | 卡片出现时 | 完成时的说明 |
|---|---|---|---|
| `rubric` | 评分标准 | 已完成 | 《名称》版本；默认取最新发布的一份时注明“确认时可以换” |
| `model` | 评分模型 | 已完成 | 连接名 · 模型，或“平台模型” |
| `files` | 选择待评分文件 | 进行中（带附件开始时已完成） | N 份 |
| `confirm` | 确认开始 | 待做 | — |
| `upload` | 上传与预检 | 待做 | N 份可以评分；移除了几份也写上 |
| `scoring` | 评分 | 待做 | 共 N 份；有没评完的写几份 |
| `report` | 汇报结果 | 待做 | — |

导入评分标准（8 步）：前两步换成 `import`“上传评分规则和模板”（进行中）、`publish`“在右侧核对并发布”（待做），去掉 `rubric`（发布的这份就是评分标准），其余同上。`model` 在卡片出现时就检查：没有可用的评分模型时标“缺”，说明“发布后要先配置模型连接”。

### 3.3 状态

步骤状态：`todo` 待做、`current` 进行中、`done` 完成、`blocked` 等你决定或缺东西、`failed` 没完成、`skipped` 跳过。

卡片状态：`running` 进行中、`done` 完成、`failed` 没完成、`dismissed` 已放弃、`expired` 已过期，另有兜底的 `ended` 已结束（见 3.5）。

### 3.4 每个节点怎么更新

| 节点 | 更新 |
|---|---|
| `begin` | 建卡片（3.2） |
| `wait_files` | `files` 完成（N 份），`confirm` 进行中 |
| `propose_start` | `rubric` 的说明换成实际用的那份（换过标准时）；找不到标准或模型（确认前被撤下）→ 卡片没完成 |
| `wait_confirm` | 确认：`confirm` 完成、`upload` 进行中；重新选文件：`files` 进行中、`confirm` 待做；不评了：`confirm` 跳过、卡片已放弃 |
| `precheck` | 通过：`upload` 完成、`scoring` 进行中；有可移除的文件：`upload` 等你决定（N 份无法评分）；有还没解析完的：`upload` 没完成、卡片没完成 |
| `wait_remove` | 先不评：卡片已放弃 |
| `remove_papers` | 移除后通过：`upload` 完成（移除 N 份）、`scoring` 进行中；没有剩下的：`upload` 没完成、卡片没完成 |
| `start_scoring` | `scoring` 的说明：共 N 份 |
| `finish_job` | 自动重试：`scoring` 说明“N 份临时性错误，已自动重试一次”；取消：`scoring` 跳过、卡片已放弃；失败且没有结果：`scoring` 没完成、卡片没完成；其余：`scoring` 完成（有没评完的写几份）、`report` 完成、卡片完成 |
| `wait_import` | 提交：`import` 完成（《名称》）、`publish` 进行中；不导入了：卡片已放弃 |
| `wait_publish` | 已发布：`publish` 完成（《名称》版本）；没有评分模型：`model` 缺、卡片没完成；否则 `files` 进行中。导入已取消、草稿过期：卡片没完成 |
| 任何 `_fail` | 进行中的那一步没完成，说明写失败原因；卡片没完成 |

### 3.5 流程被放弃、过期或意外结束

- 老师在打断确认卡片上选了“放弃并开始”、等待超过 7 天作废：运行器放弃流程时，把计划卡片标成已放弃或已过期。为此每个中断的载荷里带上计划卡片的编号（和等待中的卡片一样只有编号），运行器从 `pending` 里取。这个编号只存在会话里，`runs` 与会话接口返回的 `pending` 按字段输出，不带它。
- 兜底：流程结束时计划卡片还是“进行中”（某条结束路径漏了更新），运行器把它标成 `ended`“已结束”，不猜是成是败。测试覆盖每条已知的结束路径，兜底只防以后新增的路径。

## 4. 显示

1. **对话里的卡片**：按顺序列出步骤，每步一个状态记号（✓ 完成、● 进行中、○ 待做、! 等你决定/缺、✕ 没完成、– 跳过）、名称和说明。
2. **对话标题下的一行进度**：有进行中的计划时显示“第 3/7 步 · 选择待评分文件”；某步等你决定时写明。点击滚动到计划卡片。后面的消息越来越多，计划卡片会被顶上去，这一行让当前步骤一直看得见。
3. **右侧工作区空着时**：原来只有一句“评分的每一步会显示在这里”，有进行中的计划时改为显示这张计划。建好任务后工作区换成任务页，计划仍在对话和标题下那一行里。

## 5. 数据与接口

- 计划卡片和其它卡片一样存在 `assistant_messages.cards`（JSON），**不加迁移、不改接口**（卡片是自由字段）。卡片字段：`type: "plan"`、`flow`（`grading` / `import`）、`steps: [{key, label, status, detail}]`、`status`。
- 流程状态多一个 `plan`（计划卡片所在消息与卡片的编号），各节点据此更新；步骤本身只存在卡片里。
- `RunContext` 新增 `patch_card`：按编号改卡片的字段（现有 `update_card` 只改 `status` 与 `result`）。
- 更新过的消息本来就随运行结果返回（`updated_message_ids`），前端按编号合并，卡片原位刷新。

## 6. 与 Agent 的关系

- 计划卡片**不进 Agent 的上下文**：不加进 `CARD_LABELS`，历史里不渲染它。提示词正文、tools 与工具说明都不变，提示词指纹不变，不需要重跑评测，部署门禁照常通过。
- Agent 照旧回答流程中途的提问（“现在有评分标准吗”“这一步怎么做”），它从等待中的步骤（`PENDING_DETAILS`）知道流程停在哪。
- 以后若要 Agent 说出“还剩几步”，再把计划的摘要放进状态块；那是提示词改动，要按评测流程走。

## 7. 测试

- 后端（`test_assistant.py`）：
  - 开始评分出 7 步，前两步已完成；带附件开始时 `files` 已完成；
  - 走完整个流程，每一步按 3.4 变化，最后卡片完成；
  - 导入流程出 8 步，发布后接着评分；
  - 不评了、先不评、放弃并开始新流程（打断确认）、过期，卡片分别是已放弃、已过期；
  - 预检有还没解析完的文件、作业失败，卡片没完成；
  - 兜底：结束时还在进行中，标成已结束。
- 前端单测：卡片按状态显示记号与说明；从消息里找进行中的计划、算出“第几步”。
- 浏览器验收（`e2e/assistant.spec.js`）：说“上传我的评分规则和模板”后出现 8 步的计划卡片，标题下显示“第 1/8 步”。验收种子没有已发布的评分标准，开始评分的 7 步由后端测试覆盖。

## 8. 放弃了什么

- **让模型规划步骤（Plan–Execute）**：步骤固定，模型规划只会带来漏确认、排错序的可能，还要为提示词改动重跑评测（第 2 节）。
- **计划只放在工作区**：建好任务后工作区换成任务页，计划就看不到了；对话里的卡片加标题下的一行进度一直看得见。
- **另建一张表存计划**：计划是流程的展示，跟着消息走；不加迁移，也就没有 `pgs_app` 授权和降级的事。
- **每更新一步发一条新消息**：对话被“第几步完成了”刷屏；在原卡片上更新。
- **观察流程（重试后）也出计划**：只有一步，进度卡片已经够了。
- **兜底时猜成败**：漏更新的路径不知道结果，标“已结束”比标错好。
