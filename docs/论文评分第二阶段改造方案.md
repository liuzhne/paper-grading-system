# 论文评分第二阶段改造方案（规则判定）

状态：**分期 A–D 已实现**（2026-11-03）：A 默认打开，B、C 默认关闭，D 是只读脚本。维护者要求方案写完即实现并部署；第 2 节的决定随实现落地，可在复审时调整。真实模型评测、QWK 重新锚定与校准样本**需要维护者单独授权预算**，本轮不做。

实现时发现：已发布规则的快照（`atomic-rule-snapshot@1–3`）**不带 `applies_to`**，评分时拿不到“适用章节”。所以本轮的判定范围只从规则文字识别“跨章节”；“章节内”要等规则快照带上 `applies_to`（下一轮，见第 9 节）。

边界：
- 只改“第二阶段”：Core 路径上每条规则从取证据、模型判定到代码算分这一段（`rule_executor` → `retrieval/selection` → `llm/core_view` → 三个适配器）。
- 不改：评分标准导入与 AI 起草（起草改造暂停中）、发布校验 `rubrics/executable_validator.py`、legacy v1 路径、`SCORING_ENGINE_MODE`、人工复核页面。
- 无数据库迁移，Alembic head 不变（`0041_assistant_agent_state`）。
- 依据：2026-11-02 的长论文评分调研（RULERS、SAGE、Autorubric 等）与 2026-11-03 对另一份调研的核对（含 ARTS-Hybrid，arXiv 2610.13375）。要点见附录。

---

## 1. 结论

不把评分拆成“局部分”和“整体分”两条通道。每条规则有一个**判定范围**：章节内、跨章节、全文。范围只决定证据怎么取、由谁判；分数仍由代码从同一套规则判定结果算出，整体部分不单独出分。

```text
已发布的评分标准版本
  │  每条规则推断判定范围（代码，可复现）
  ├─ 全文 ────→ 有检查器的走确定性检查器；其余语义规则按现状全文多样化取证
  ├─ 章节内 ──→ 只在目标章节里选证据；找不到目标章节时退回全文并告诉模型
  └─ 跨章节 ──→ 每个目标章节各取证据，交替排列
        │
        ▼  预算检查：量实际发给模型的内容（不再量带哈希的完整信封）
     模型判定：triggered / not_triggered / not_applicable / insufficient_evidence（新）
        │  引文逐字校验（现状）
        ▼
     代码算分；有“证据不足”的评分项 → review_required，自动分保留、最终分等人工定
```

四项改动，三个设置（都从 GitHub 仓库变量传进生产，没设即取默认值，见 RUNBOOK）：

| 分期 | 改动 | 开关（默认值） | 是否改变分数 |
|---|---|---|---|
| A | 预算检查量实际发送的内容 | `SCORING_TOKEN_BUDGET_TARGET=provider_view` | 是：放得下的证据变多，之前判失败的规则能出结果 |
| B | 判定范围与按范围取证 | `SCORING_JUDGE_SCOPE_ENABLED=false` | 打开后是 |
| C | “证据不足”状态与反证检查 | `SCORING_INSUFFICIENT_EVIDENCE_MODE=off` | 打开后是 |
| D | 规则体检报表（只读脚本） | 无 | 否 |

## 2. 决定

| # | 决定 | 放弃了什么 | 为什么 |
|---|---|---|---|
| D1 | 判定范围标在规则上，分数只从规则判定结果算 | 局部、整体两条通道各自出分 | ① “长文档必须拆两条独立通道”在 LongJudgeBench 摘要里没有，读到的论文都没做过这种对照；② 同一缺陷会在两路各扣一次；③ “局部分 + 整体分”不是用户模板给的汇总结构 |
| D2 | 本轮在评分时由代码推断范围，记入证据选择身份；不写进规则快照 | 规则快照升 `@4` 存范围与 `applies_to`、规则审查页可改 | 存进快照要改导入、版本哈希、审查页和发布流程，范围大。代价：已发布快照不带 `applies_to`，本轮只能从规则文字认出“跨章节”，“章节内”放下一轮（第 9 节） |
| D3 | 范围只从用户授权的字段和规则文字推断，不让 AI 定 | AI 标注范围 | 确定性优先；推断规则带版本号，可复现 |
| D4 | 预算改量实际视图，并默认打开 | 只把 `SCORING_CONTEXT_WINDOW_TOKENS` 调到 32768；或默认关闭等评测 | 调窗口能绕开报错，但量错对象的问题还在。这是让整份论文判失败的 bug，修复后才符合原设计（最多 12 段证据）。代价是分数可能变化，QWK 待授权后补做 |
| D5 | 新增 `insufficient_evidence`，评分项进 `review_required`，自动分照算、最终分留空 | 证据不足默认不扣分（现状）；默认扣分 | 两种默认都会系统性偏一个方向。`review_required` 已有，人工可以定分；不会变成不能改分的 `invalid` |
| D6 | 证据不足在规则判定里记为 `not_triggered` 加一条 `review` 级问题，不新增判定状态 | 规则判定状态新增 `insufficient_evidence` | 判定状态是闭合契约，牵动结果、持久化、报告、导出与前端；问题列表与 `review_required` 已有整条链路 |
| D7 | 反证检查写进判定规则，不加调用轮次 | DeepReview 式多阶段调用 | DeepReview 是训练出来的模型的思维链；多一轮成本翻倍；生产 Gemini 关闭了思考，自由推理难校验 |
| D8 | B、C 默认关闭，部署后由维护者在评测后打开 | 直接默认打开 | 改评分逻辑要先用 QWK 留出集对比（项目约定），真实模型调用需要授权预算 |
| D9 | 不扩大依赖门控、不做层级汇总、不做多评委 | ARTS 式自上而下路由；多智能体 | ARTS-Hybrid 中自上而下路由 6 组实验全部变差、层级汇总无稳定收益；作文研究中多评委 4 倍调用只多 0.0288 QWK |
| D10 | 规则体检只出报表，不自动改规则 | 按统计自动降权、合并规则 | 模型自审会删掉有用规则（Shapley 归因那篇）；改规则要人确认并发新版本 |

## 3. 现状（核对过代码）

### 3.1 一条规则现在怎么判

1. 按评分标准版本生成执行计划，依赖按拓扑序（`rule_executor.py` `_topological_order`）。
2. 确定性规则由检查器判，不调模型。论文 Profile 有 6 个检查器：必备章节、字数、图表引用、引文与参考文献、格式、研究—结论结构（`profiles/thesis.py` `THESIS_CHECKER_KEYS`）。
3. 依赖规则没触发时本规则直接跳过；导入时依赖默认为空。
4. 语义规则选证据（`selection.py` `build_v4_envelope`）：BM25 + 章节多样化，最多 `SCORING_EVIDENCE_TOP_K=12` 段。规则名、档位、finding_code 带“缺失/缺少”等词时切成 `exhaustive`；带“一致/对应/贯穿”等词时标成 `hierarchical`，但取法与 `top_k` 相同。
5. 预算检查量的是完整信封（带哈希、运行身份、全部参考文献与未压缩证据），超了就从末尾删证据，删光或 `exhaustive` 放不下就报 `TOKEN_BUDGET_UNSATISFIABLE`。
6. 发给模型的视图（`core_view.py` `_view`）：每段最多 400 字、证据合计最多 3000 字；附 `paper.digest`、所属评分项、按需的参考文献与一致性发现。证据只显示最后一级标题。
7. 三个适配器发送前再按实际视图预检一次（`preflight_core_request`）。
8. 引文须逐字出自证据，finding_code 须在白名单。
9. 代码算分；`effect_type=review` 的规则触发时评分项为 `review_required`。

### 3.2 问题

| 问题 | 位置 | 后果 |
|---|---|---|
| 预算量信封而不是实际视图 | `selection.py` 删证据的循环 | 证据被多删；另一会话在本地合成论文上测得信封约 5610 token、实际视图约 1564 token，只放得下约 3 段（分期 A 测试里复测） |
| `exhaustive` 要求整篇放下 | 同上 | 真实论文放不下，这条规则判失败，整份论文失败 |
| “现有证据不足以证明缺陷”算 `not_triggered` | `core_view.py` 系统提示词 | 没看到就当没问题，偏向少扣分 |
| `applies_to`（适用章节）不参与选证据 | 只在快照与契约里出现 | 写了章节的规则仍在全文里检索 |
| 跨章节规则没有成对取证 | `hierarchical` 只是标签 | “研究问题在结论中是否回应”可能只拿到一端 |
| 证据只显示最后一级标题 | `core_view.py` `_view` | 模型不知道段落属于哪一章 |

### 3.3 未验证

- 真实论文的章节标题识别率（解析层 `section_path`）。模板解析那边发现无样式中文标题识别不到，论文解析是另一套代码，没测过。
- 现有已发布评分标准里，多少规则会被推断成每种范围。
- 打开 C 后“证据不足”的比例，以及多少份论文因此进入人工复核。

## 4. 分期 A：预算检查量实际发送的内容

- `build_v4_envelope` 删证据时，用 `core_view` 生成与实际请求相同的视图（单条规则用单条提示词，互斥组用组提示词和全部成员规则），按 `request_input_estimate` 的口径估算。适配器发送前的预检保留，作为最后一道。
- 新参数 `request_rules`：实际进入请求的规则。`SCORING_EVIDENCE_SCOPE=criterion` 时，选证据按整个评分项共享，但请求里只有本条规则或本互斥组，估算按后者。
- 量对之后 `exhaustive` 不会再因放不下而失败：视图里的证据本来就受 3000 字上限约束，模型实际看到的是排名靠前、合计不超过 3000 字的段落。“整篇都没有”这类判断本来就不可靠，由 B、C 处理。
- 预算身份 `policy_version` 升到 `provider-context-budget@2`；`estimated_input_tokens` 记视图估算值。
- 回退：`SCORING_TOKEN_BUDGET_TARGET=envelope` 恢复旧量法，身份也回到 `@1`。

不改：`SCORING_CONTEXT_WINDOW_TOKENS` 默认 9040；单段 400 字、合计 3000 字的压缩上限（`评分请求token压缩方案.md`）。

代价：判定身份变化（预算身份在信封里），决策账本里的已有判定不能复用，重评会重新花钱，分数可能变化。

## 5. 分期 B：判定范围

### 5.1 三种范围

| 范围 | 例子 | 证据怎么取 |
|---|---|---|
| `section` 章节内 | 适用章节写了“系统设计”的规则 | 只在目标章节里按 BM25 选段；找不到目标章节时退回全文，视图标 `found=false` |
| `cross_section` 跨章节 | 研究问题在结论中没有回应；摘要与结论不一致 | 每个目标章节各自排名，交替取，合计不超过 `top_k`；某一章找不到时标 `found=false` |
| `document` 全文 | 整体语言规范；参考文献；字数 | 与现状完全相同（确定性规则本来就不取证据） |

### 5.2 推断规则（`judge-scope@1`，代码，可复现）

1. 确定性规则 → `document`。
2. 规则的 `applies_to` 不是 `global`/`全文`/空 → 按“、，,;；/”拆开：1 个 → `section`；2 个及以上 → `cross_section`。规则的 `applies_to` 在导入时继承评分项，来自 Excel 的“适用范围/适用章节/作用范围”列，是用户授权的内容。**本轮不生效**：已发布快照不带这个字段，代码已按它写好，等快照带上后生效。
3. 规则名称或正文含“一致、对应、呼应、回应、贯穿、闭环、前后”之一，且能从文字里认出两个不同的章节角色 → `cross_section`。
4. 其余 → `document`。

章节角色是一张同义表（如“绪论 / 引言 / 前言 / 研究背景 / 研究问题 / 研究目标”都指绪论，“结论 / 总结 / 结语 / 结束语 / 研究结论”都指结论）。章节匹配先去掉“第 X 章”“3.2”这类编号，再按“互相包含”匹配标题路径中的任一级，和模板批注挂评分项的做法一致；目标是角色名时，命中该角色的任一同义词即可。

共享选证据（互斥组、`SCORING_EVIDENCE_SCOPE=criterion`）时，按共享规则里规则编号最小的一条推断，保证成员拿到同一组证据。

### 5.3 身份与契约

- 只有推断为 `section` / `cross_section` 时才改变选证据：`coverage_mode` 记为 `section` / `cross_section`（`PromptEnvelopeV4` 契约放开这两个值），`selector_version` 记为 `section-bm25-diverse@2+judge-scope@1`。推断为 `document` 的规则身份与现状完全相同。
- 开关打开时，视图里的证据显示完整标题路径（如“第 3 章 系统设计 › 3.2 数据库设计”）；`section` / `cross_section` 规则另带 `scope`：`{"type": "...", "targets": [{"name": "绪论", "found": true}, ...]}`，跨章节的证据项带 `target`。系统提示词加一句说明这些字段。
- 提示词有变化时，Provider 提示词版本加后缀 `+judge-scope@1`，进入运行身份与判定身份；关闭时不变。

## 6. 分期 C：证据不足与反证检查

### 6.1 四种状态

| 状态 | 含义 | 计分 |
|---|---|---|
| `triggered` | 证据显示存在缺陷，必须逐字引用（现状） | 按规则扣分 |
| `not_triggered` | 证据覆盖了规则要检查的内容，且显示不存在缺陷；包括作者已说明原因、限定范围或给出替代做法 | 不扣 |
| `not_applicable` | 规则的适用前提在本文不成立（现状） | 不扣 |
| `insufficient_evidence`（新） | 给出的证据没有覆盖规则要检查的内容，无法判断 | 不扣，评分项转人工 |

提示词把“或现有证据不足以证明缺陷存在”从 `not_triggered` 中拿掉，改为：判 `triggered` 前先检查证据中作者是否已说明原因、限定范围或给出替代做法，已说明则判 `not_triggered`；证据没有覆盖规则要检查的内容时判 `insufficient_evidence`。输出结构不变，只是 `status` 多一个取值。

### 6.2 计分与转人工

- 模型回 `insufficient_evidence` 时，规则判定记为 `not_triggered`（扣分为 0），同时记一条 `review` 级问题 `RULE_EVIDENCE_INSUFFICIENT`；规则任务状态因此为 `review_required`（现有逻辑）。
- 所属评分项为 `review_required`：自动分照算，最终分留空，论文总分等人工定。band 评分项的档位规则证据不足时同样是 `review_required`，自动分为空。
- 决策账本照常缓存这类判定（它是合法回复），重评不重复花钱。
- 开关：`off`（默认，提示词与输出结构完全是现状）｜`review`（新提示词，状态多一个取值）。`review` 下 Provider 提示词版本加后缀 `+insufficient@1`。

### 6.3 监控

打开后按规则统计证据不足率（第 7 节报表）。某条规则长期很高，说明取证或规则文字有问题；全局很高，说明人工复核量会失控，应先切回 `off`。

## 7. 分期 D：规则体检报表

`python -m backend.app.scripts.rule_health_report --batch-id <批次>`：只读 `rule_scoring_tasks` 与 `review_logs`，不调模型、不改分。每篇论文取最近一次评分。

| 指标 | 算法 | 提示什么 | 依据 |
|---|---|---|---|
| 零区分度 | 有效判定 ≥ 5 篇，且全部触发或全部未触发 | 规则可能没在看论文 | Rubric Artifacts、POW3R |
| 经常一起触发 | 两条规则同时触发的篇数 / 任一触发的篇数 ≥ 0.8，且同时触发 ≥ 3 篇 | 可能重复扣分，考虑互斥组或封顶 | RRD |
| 人工推翻 | 评分项里只有这一条规则触发，且人工改分后分数高于改前 | 规则可能误扣 | Shapley 归因、RART |
| 证据不足率 | 判定未触发但规则任务为 `review_required` | 取证或规则文字有问题 | — |
| 判失败率 | `invalid` | 规则或取证有问题 | — |

阈值是初值；样本不足时只列计数，不下结论。

## 8. 校准样本与评测（需要授权，本轮不做）

- 样本：30–50 篇双人评过的论文，12–20 篇做示例，其余只做验证，按评分项分别算一致性（数量是估计，论文没有直接给出）。
- 用途：填规则的正例、反例、边界例；用边界例做发布前“正反例试判”（对正、反例判出同样结果的规则没在看文章，这是从 Rubric Artifacts 的发现推出的做法）；QWK 留出集。
- 评测顺序：A 上线后、打开 B 前后、打开 C 前后各一次，分别对比 QWK 与费用，决定 B、C 的默认值，以及是否放宽 3000 字证据上限。

## 9. 不做的事

- 局部、整体两条独立打分通道（D1）。
- 多智能体辩论、多评委投票；扩大依赖门控；按层级汇总；调评分项权重（D9；德语毕业论文研究中调权重偏差 11.18% → 10.85%，不显著）。
- 把判定拆成多轮调用（D7）。
- AI 自动改写规则（D10）。
- 打开语义一致性核验：它的“正文摘要”是全文前 4000 字（`coherence/semantic.py`），长论文的“结论缺乏支撑”会偏向误报；要用先改成按章节取证，单列方案。
- 下一轮再做：`applies_to` 与判定范围写进规则快照（`atomic-rule-snapshot@4`），让“章节内”生效，并在规则审查页显示、修改；对“语义规则 + 名称带缺失类词”的规则提示改用结构检查器；解析层检查隐藏文字（防注入）。

| 预算身份 | `provider-context-budget@2`（A 默认） | `SCORING_TOKEN_BUDGET_TARGET=envelope` |
| 费用估算 | 不变：`usage_estimate` 本来就按实际视图估算 | — |
| 选证据身份 | 只有 `section` / `cross_section` 规则变 | `SCORING_JUDGE_SCOPE_ENABLED=false` |

## 11. 验收

- A：Mock 全量测试通过；合成长论文上，旧量法会失败的场景（超长段落、参考文献很多、规则名带“缺失”）不再失败；视图估算明显小于信封估算。
- B：Mock 测试覆盖三种范围、目标章节缺失、跨章节一端缺失、共享选证据的成员一致；开关关闭时身份与现状相同。
- C：Mock 测试覆盖单条与互斥组的证据不足、band 评分项、账本复用；`off` 时提示词与结构与现状相同；`review_required` 评分项可人工定分。
- D：合成数据上指标正确。
- 真实模型 QWK：待授权（第 8 节）。

## 12. 风险

- 章节识别不准 → 章节内规则拿错证据。找不到就退回全文并告诉模型；打开 B 前先用真实论文看识别率。
- 证据不足过多 → 人工复核量暴增。C 默认关闭，打开后看报表。
- A 改变分数且暂无 QWK 对比。可以用开关回退；授权后补评测。
- 研究依据多来自短文和偏好评测集，用到中文毕业论文是外推。
