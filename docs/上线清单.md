### 14.2 部署顺序不能反

新代码启动即读 `platform_llm_config`。**先部署代码后迁移**，那段时间里读表会失败，
`_platform_runtime()` 按设计不回落 Mock，于是全站 LLM 动作报「尚未配置平台模型」。

读该表的两处（`/system/capabilities`、`/system/platform-llm`）已对「表不存在」容错，
读不到即视为「没有平台模型」，因此顺序反了不会整站崩。**但这是防线不是许可**：
`capabilities` 是前端启动就读的，它 500 会让整个工作台起不来。

正确顺序：

1. `pgs-production-migrate` 工作流，`expected_head=0030_platform_llm_config`，
   先 `dry_run=true` 看清当前版本与行数，再 `dry_run=false`；
2. 确认工作流的「Verify with the runtime role」通过——它用 `pgs_app` 复验，
   owner 什么都读得到，证明不了应用能不能工作；
3. 再合并到 main，由 CI 触发 Vercel 部署。

### 14.3 上线后必然出现的状态（这是期望行为）

迁移与部署完成后，生产进入「平台未配置模型」：

- 所有用户登录后被引导到「账户与连接」；
- 平台管理员可在「运维与质量 → 平台默认模型」配置，配好后全体恢复正常。
