# 论文评分韧性改造执行计划

> 执行基线：2026-09-04；对应方案为《论文评分规则级检索、并发、容错与人工复核改造方案》。默认 `SCORING_ENGINE_MODE=legacy`，未取得真实 GATE-03 前不得切换。本文只引用合成测试数据，不包含用户论文、学生 PII 或生产 Secret。

## 1. 发布目标

本轮候选版本解决两个直接生产风险：

1. 单条语义评分请求因上下文、限流、容量或 Provider 故障失败时，不再终止整篇论文的所有规则。
2. 必需规则无法自动完成时，不生成貌似完整的总分；系统创建可领取、带版本控制且必须引用冻结原文证据的人工复核任务。

同时建立最小上下文选择、请求前预算校验、Provider 错误合同、Langfuse 诊断投影和按连接的进程内保护层。

## 4. 配置与回退

| 配置 | 候选默认 | 回退用途 |
|---|---:|---|
| `SCORING_ENGINE_MODE` | `legacy` | 保持不变；不是本次切换项 |
| `SCORING_PROMPT_ENVELOPE_VERSION` | `v4` | 仅在已证明输入安全时短期退 `v3` |
| `SCORING_RULE_TASKS_ENABLED` | `true` | 紧急关闭新检查点写入；不删除历史任务 |
| `MANUAL_REVIEW_QUEUE_ENABLED` | `true` | 关闭只停止新任务，既有阻塞仍不得伪造总分 |
| `PROVIDER_CIRCUIT_BREAKER_ENABLED` | `true` | 误熔断时短期关闭并降低外层批并发 |
| `PROVIDER_GLOBAL_CONCURRENCY` | `4` | 根据账户真实限制下调，不自动上调 |
| `LLM_OBSERVABILITY_ENABLED` | `false`（无凭据时） | Exporter 异常立即关闭，不影响业务库 |

数据库默认采用向前修复。0023 已有数据时禁止有损 downgrade；应用需要回滚时部署兼容旧代码前先确认其不会访问新工作流，数据库保留 0023 表和审计记录。

## 5. 后续迭代进入条件

- 向量检索：必须先有 Recall@K 标注集、数据驻留批准、embedding 版本和重建策略；小规模优先 PostgreSQL/pgvector，不因“用了向量”单独引入新数据库。
- DAG 并发：必须先完成执行前任务持久化、租约恢复、全局配额和重复扣费证明。
- 自动重试：必须证明 Envelope/hash/模型/service tier 不变，并限制总 attempt 与总费用。
- Core 默认切换：必须有真实外部 holdout、QWK/MAE/公平性/复核率、完整 frozen identity、`gating_eligible=true` 和维护者批准。

## 6. 当前交付判定

代码完成不等于生产完成。只有全套本地测试、Postgres CI、恢复演练、PR 合并、生产部署与冒烟都成功，本轮候选版本才能标记“已上线”。向量检索、规则级中断恢复、DAG 并发、分布式限流和 Groq Batch 在各自工作包完成前保持“未实现”。

当前本地证据（2026-09-04）：Python 3.12 全套 `1463 passed, 48 warnings`；`compileall`、`git diff --check` 通过；SQLite 空库 0001→0023、0023→0022、0022→0023 重放通过，有任务数据时 0023 fail-closed 用例通过。当前工作区没有获授权的真实教师 holdout，因此未运行真实 QWK/GATE-03；默认 legacy 边界保持不变。
